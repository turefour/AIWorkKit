# 平台接入指南

AIWorkKit 不绑定任何特定 AI 编程平台。任何能发起 HTTP 请求、或能被命令包一层的工具，
都可以把任务进度与资源占用接进来看板。

---

## 1. 端口与角色

| 服务 | 默认端口 | 角色 | 是否必需 |
|---|---|---|---|
| CodeVault | 57910 | 项目索引库（主界面 + 设置页） | 是（入口） |
| Eco | 57821 | 降耗模块：事件汇总、进度与资源监控 | 否 |
| Tuner | 57822 | 进程降温：内存回收、优先级、挂起 | 否 |
| errvault | 57911 | 报错库：报错/卡死/拦截的解法索引 | 否 |

端口在 `config/deploy.json` 的 `ports` 里改，四个服务启动时读取同一份配置。
旧版（CodeBuddyWorkKit）用的是 47/48 段，本项目用 57 段，两者可以同时运行不冲突。

## 2. 标准事件协议

唯一入口：`POST http://127.0.0.1:57821/api/events`

### 2.1 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `platform` | string | 否 | 来源平台标识，缺省 `generic` |
| `event` | string | 否 | `turn.start` / `turn.end` / `tool.start` / `tool.end` / `usage` |
| `sessionId` | string | 否 | 会话标识，同一会话的任务会归并显示 |
| `job` | object | 否 | 任务条目，见下表 |
| `payload` | object | 否 | 工具层细节（命令、耗时、退出码） |

`job` 子字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 任务唯一 id，相同 id 会更新同一条 |
| `kind` | string | 分类（build / test / edit / explore …） |
| `label` | string | 显示名 |
| `status` | string | `running` / `done` / `failed` / `cancelled` |
| `current` / `total` | number | 进度分子分母，用于百分比 |
| `unit` | string | 进度单位 |

### 2.2 最小示例

```json
{ "event": "tool.end", "job": { "id": "r1", "label": "npm test", "status": "done" } }
```

`job.id` 缺省时会用 `sessionId` 或进程号兜底，所以**最简一行也能上报成功**。

### 2.3 完整示例

```json
{
  "platform": "codex",
  "event": "tool.end",
  "sessionId": "sess-7f3a",
  "job": {
    "id": "run-20261124-001",
    "kind": "build",
    "label": "npm run build",
    "status": "done",
    "current": 8,
    "total": 8,
    "unit": "step"
  },
  "payload": { "tool": "Bash", "command": "npm run build", "exitCode": 0, "durationMs": 4210 }
}
```

响应：`{ "ok": true, "accepted": true }`，HTTP 204/200。

## 3. 三种接入方式

### 3.1 直接 HTTP（最简单，任何语言）

```bash
curl -X POST http://127.0.0.1:57821/api/events \
  -H "content-type: application/json" \
  -d '{"event":"tool.end","job":{"id":"r1","status":"done"}}'
```

适用于：Vibe Coding 这类支持自定义 webhook / 脚本的平台。

### 3.2 命令包装（适合 CLI 型平台）

`apps/eco/adapters/codex.mjs` 把任意命令包一层，自动上报开始/结束/耗时/退出码：

```bash
node apps/eco/adapters/codex.mjs --label "跑测试" -- npm test
```

- 命令的 stdout/stderr 原样透传，不影响原有输出
- 退出码保持原命令的退出码，脚本链和 CI 行为不变
- 参数不经 shell 拼接，直接透传

改成别的平台（如 Codex 之外的 CLI）只需复制这个文件改 `platform` 字段。

### 3.3 事件流（适合 Harness 型平台）

`apps/eco/adapters/deepseek.mjs` 从标准输入读「一行一个 JSON」：

```bash
some-harness --emit-events | node apps/eco/adapters/deepseek.mjs
```

支持两种行格式：

- **标准事件**：`{"event":"tool.end","job":{...}}`
- **简写**：`{"tool":"Bash","ok":true,"ms":420}` → 自动映射成 `tool.end`

边跑边处理，任务没结束就能在看板上看到进度。

### 3.4 通用文件输入

```bash
echo '{"event":"tool.end","job":{"id":"r1"}}' | node apps/eco/adapters/generic.mjs
node apps/eco/adapters/generic.mjs event.json
```

---

### 3.5 插件清单（可选）

如果平台以「插件目录」形式接入，清单放在插件根目录：

```
my-plugin/
  .aiplugin/plugin.json          ← 通用约定（推荐）
  .codebuddy-plugin/plugin.json  ← 历史约定，仍然兼容
  hooks/hooks.json               ← 可选：hook 声明
```

`plugin.json` 至少要有 `name`，可选 `version` / `description` / `hooks`。
两种位置同时存在时**优先 `.aiplugin`**，老插件包不用改就能继续被识别。

## 4. 新增一个平台

1. 在 `config/platforms.json` 的 `platforms` 里加一条：

```json
"myplatform": {
  "label": "My Platform",
  "configDir": "~/.myplatform",
  "rulesDir": "~/.myplatform/rules",
  "settingsFile": "~/.myplatform/config.json",
  "pluginsDir": "~/.myplatform/plugins",
  "eventSource": "http",
  "note": "通过 webhook 上报标准事件"
}
```

2. 装规则（写到该条目的 `rulesDir` + `ruleFile`）：

```powershell
# 先看会写哪些，不落盘
powershell -File tools\install-rules.ps1 -Target <套件目录> -Platforms all -Dry

# 只装一个平台
powershell -File tools\install-rules.ps1 -Target <套件目录> -Platforms myplatform

# 全部平台
powershell -File tools\install-rules.ps1 -Target <套件目录> -Platforms all
```

`installMode` 决定写法：

| 值 | 行为 |
|---|---|
| `file` | 整份写进 `rulesDir/ruleFile`（独占文件，卸载时直接删） |
| `block` | 追加/替换 `rulesDir/ruleFile` 里 `<!-- AIWorkKit:BEGIN -->` 包裹的区块（适合 `AGENTS.md` / `CLAUDE.md` 这种聚合文件） |

`probe` 是「本机装没装这个平台」的判断依据，`-Platforms auto` 只装探测到的平台。

3. 上报事件（任选 §3 中的一种）。

平台清单会出现在设置页「已登记平台」里，不需要改前端。

## 5. 降耗模块配置

设置页（CodeVault → 设置）可改：采样间隔、CPU 阈值、内存阈值、降耗冷却、是否允许自动降耗。
也可以直接调接口：

```bash
curl http://127.0.0.1:57821/api/config
curl -X POST http://127.0.0.1:57821/api/config \
  -H "content-type: application/json" \
  -d '{"cpuThreshold":70,"scanIntervalMs":8000}'
```

配置落在 `apps/eco/.eco/settings.json`，与进程状态文件分开（后者会在退出时被重写）。

## 6. 报错库写入

```bash
curl -X POST http://127.0.0.1:57911/api/entry \
  -H "content-type: application/json" \
  -d '{
    "kind": "blocked",
    "symptom": "The process cannot access the file",
    "scope": "machine",
    "repro": "always",
    "severity": "major",
    "cause": "dll 被加载",
    "fix": "改名后删，或重启后删"
  }'
```

同一个 `symptom` 再次提交不会新建记录，而是把出现次数加一。
完整的接口清单（含请求/响应格式）在设置页「接口目录」里，点「查看格式」即可展开。
