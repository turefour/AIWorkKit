# memcore · 统一任务记忆

本文件是「记忆库」的规范说明：它是什么、放在哪、什么能进来、怎么读怎么写、怎么验证。
面向使用者与后续接手的 AI 任务，**改实现前先读这一页**。

---

## 1. 并入后的套件结构

```
<部署目录>\
├─ apps\
│  ├─ codevault\          索引库（Web，页面里的「记忆库」面板指向 memcore）
│  ├─ pulse\  tuner\      看板 / 降温（57821 / 57822）
│  ├─ errvault\           报错库（57911）—— 报错与解法归它
│  ├─ memcore\            记忆库（57912）—— 习惯、方向、决策归它
│  │  ├─ server.mjs       HTTP 服务（/api/health、/api/note、/api/search…）
│  │  ├─ lib\paths.mjs    归档根解析（MEMCORE_HOME → <套件根>\memory）
│  │  ├─ lib\store.mjs    索引读写、条目校验、检索打分、日志
│  │  ├─ lib\sources.mjs  只读读取会话索引 / 消息队列 / 项目清单
│  │  ├─ lib\extract.mjs  习惯、方向、关键词的规则抽取
│  │  ├─ lib\render.mjs   生成 MEMORY.md 与 memcore.mdc（含预算裁剪）
│  │  ├─ lib\api.mjs      编排：sync / build / search / note / prune / install
│  │  └─ web\index.html   记忆浏览器（记忆正文 / 条目 / 检索 / 规则 / 数据源）
│  └─ _shared\            共享 HTTP 骨架（memcore 复用，不另起一套）
├─ tools\
│  ├─ memcore.mjs         命令行（不依赖服务在跑）
│  └─ launch.mjs stop.mjs 按 config\deploy.json 的端口启停（含 memcore）
├─ memory\                ← 唯一记忆归档，位于 apps\ 之外，重新部署不会覆盖
│  ├─ store.json          原始事件：会话元数据 + 用户指令 + 人工条目
│  ├─ MEMORY.md           完整记忆（按需读，预算 6 KB）
│  ├─ memcore.mdc         常驻规则（每会话注入，预算 1.2 KB）
│  ├─ archive\notes-YYYYMM.jsonl   条目追加镜像（审计 / 回滚）
│  └─ logs\memcore-YYYYMM.log      运行日志（按月，1 MB 轮转）
└─ config\
   ├─ deploy.json         端口与清单（deploy.ps1 生成，缺键会自动补齐）
   └─ memcore.json        可选覆盖：预算、保留天数、条数上限
```

设计约束（改成别的形态前先想清楚）：

| 约束 | 原因 |
|---|---|
| 数据放 `memory\`，代码放 `apps\memcore\` | `deploy.ps1` 整体覆盖 `apps\*`，放里面会被冲掉 |
| 端口取 `57912`（479xx = 库类号段） | 57910 索引库 / 57911 报错库 / 57912 记忆库 |
| 旧 `deploy.json` 缺 `ports.memcore` 时兜底 57912 | 升级场景不强制 `-ResetConfig` |
| 只写 `127.0.0.1`，写请求要同源 + JSON | 复用 `_shared/httpserver.mjs` 的守卫 |
| 不引第三方依赖 | 随包 Node 24 自带 `node:sqlite`，无需安装 |

## 2. 记忆条目规范

### 2.1 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 自动 | `MEM-YYYYMMDD-HHMMSS-xxxx`，写回时用它定位 |
| `type` | 是 | `habit` / `preference` / `constraint` / `direction` / `decision` / `lesson` / `task-end` / `pointer` |
| `scope` | 否 | `machine`（整机）/ `suite`（本套件）/ `project` / `session` / `task` |
| `text` | 是 | **≤200 字**，一句话结论，不写过程 |
| `tags` | 否 | ≤8 个，逗号分隔 |
| `confidence` | 否 | `confirmed`（人工确认，默认）/ `inferred`（规则抽取）/ `stale`（待复核） |
| `weight` | 否 | 1–5，默认 3；常驻规则按类型 + 权重排序取前 6 |
| `ttl` | 否 | `never`（默认）/ `180d` / `30d`，仅作复核提醒，不自动删除 |
| `source` | 自动 | `{ kind: cli\|http\|chat, at }` |
| `count` / `at` / `updatedAt` / `rev` | 自动 | 合并计数、首次写入、最后更新、修订号 |

### 2.2 类型与判定标准（什么能进来）

| 类型 | 收什么 | 判定标准 | 反例（不收） |
|---|---|---|---|
| `constraint` | 红线、必须遵守 | 用户明确“必须/不要/禁止/一律”，且换项目仍成立 | “这次先不改样式” |
| `habit` | 做事方式 | 跨 ≥2 个项目重复出现，或“以后/每次/默认” | “把按钮往左挪 4px” |
| `preference` | 风格 / 语言 / 格式 | 长期有效，不是单次排版要求 | “这页标题用 18px” |
| `direction` | 任务方向 | 一条任务线的目标（会话标题或首条指令） | “再试一次” |
| `decision` | 选型定稿 | 有理由、有被否方案；改主意时更新同一条 | “先看看” |
| `lesson` | 踩坑结论 | 一句可用结论，细节记 errvault | 完整报错栈、三次试错过程 |
| `task-end` | 收尾摘要 | 目标 / 产出 / 验证 / 未完成 四要素 | 流水账 |
| `pointer` | 外部索引 | 指向 CodeVault 项目、errvault 条目或脚本文件 | 正文超过 200 字的文档 |

**硬性排除**：助手自己的输出（只收用户侧）、`npm-debug.log` 之类日志、密钥 / token / 个人隐私、
一次性业务数据（如某一批表格记录）、超过 200 字的正文（改存文件 + `pointer`）。

### 2.3 原始事件（自动摄入，不需人工）

`store.json` 里另有两类只读数据，由 `sync` 维护：

- `sessions`：会话 id → 标题 / 目录 / 状态 / 时间（来自平台会话索引）
- `messages`：用户指令，单条截断 240 字，保留 365 天 / 最多 3000 条

它们只作抽取与检索的原料，**不直接进上下文**；进上下文的是 `MEMORY.md` 与 `memcore.mdc`。

## 3. 读取 / 引用 / 更新流程

### 3.1 读（任务开始时）

| 场景 | 动作 | 成本 |
|---|---|---|
| 每次会话 | `memcore.mdc` 由规则目录自动注入 | ≈250 tokens |
| 需要完整记忆 | `node tools\memcore.mjs show` | ≈500 tokens |
| 需要某段历史 | `node tools\memcore.mjs search <关键词>` | 命中才付 |
| 只想看统计 | `node tools\memcore.mjs stats` | 几十字 |
| 页面浏览 | `http://127.0.0.1:57912/` 或索引库侧栏「记忆库」面板 | — |

检索会同时命中三类来源：记忆条目、历史指令、会话标题（输出带 `[条目/指令/会话]` 标签）。

### 3.2 写（任务进行中 / 收尾时）

```powershell
# 长期约束（写着会自动重建 MEMORY.md 与 memcore.mdc）
node tools\memcore.mjs note add --type constraint --scope machine --text "所有 .ps1 必须 UTF-8 带 BOM" --tags powershell,bom

# 任务收尾
node tools\memcore.mjs note add --type task-end --scope task --text "目标…；产出…；验证…；未完…" --tags workkit
```

合并规则：同 `type` 且正文完全一致或相似度 ≥0.82 → 合并到原条目（`count+1`、`rev+1`、`id` 不变）。
因此“同一个坑又踩一次”“同一条约束再提一次”不需要新建。

### 3.3 更新与维护

| 动作 | 命令 | 说明 |
|---|---|---|
| 增量摄入 | `memcore.mjs sync` | 幂等；只新增未见过的会话/指令 |
| 重建产物 | `memcore.mjs build` | 只读事件，重新生成两份产物 |
| 日常刷新 | `memcore.mjs`（默认 sync+build） | 对话结束后跑一次 |
| 安装常驻规则 | `memcore.mjs install` | 写 `~\.codebuddy\rules\memcore.mdc`（已存在的 cursor/windsurf 也写） |
| 裁剪 | `memcore.mjs prune` | 按 365 天 / 3000 条 / 2000 条条目裁剪 |
| 删除条目 | `memcore.mjs note del <id>` | 同时重建产物 |

### 3.4 与 errvault / CodeVault 的分工

- **errvault**：报错原文、根因、可执行解法、复现代码 → `lesson` 条目只留一句结论 + 指向 errvault
- **CodeVault**：项目结构、构建逻辑、已知问题 → `pointer` 条目指向项目 id
- **memcore**：用户习惯、任务方向、决策、约束、收尾摘要 → 唯一长期记忆

## 4. 验证并入成功与记忆生效

### 4.1 并入（结构与进程）

```powershell
# 1) 服务是否属于本套件
Invoke-RestMethod http://127.0.0.1:57912/api/health
# 期望：ok=True, app=memcore, port=57912

# 2) 配置是否带 memcore（旧配置会被 deploy.ps1 自动补齐）
node -e "const c=require('C:/Users/GH/AppData/Local/CodeBuddyWorkKit/config/deploy.json');console.log(c.ports.memcore, c.apps)"

# 3) 端到端自检（文件层 + 进程层 + 接口层）
powershell -ExecutionPolicy Bypass -File tools\test-deploy.ps1 -Target <部署目录>

# 4) 随时体检
powershell -ExecutionPolicy Bypass -File tools\health-check.ps1 -Target <部署目录>
```

### 4.2 记忆是否正确生效

| 检查点 | 期望结果 |
|---|---|
| 归档目录 | `<部署目录>\memory\` 下同时有 `store.json`、`MEMORY.md`、`memcore.mdc` |
| 数据规模 | `memcore.mjs stats` 的会话/指令数与平台一致（会话数≈历史会话数） |
| 体积预算 | `MEMORY.md` ≤ 6 KB，`memcore.mdc` ≤ 1.2 KB（超了会整段裁剪，说明条目写太长） |
| 常驻注入 | `~\.codebuddy\rules\memcore.mdc` 存在，内容首行是 `---`，含 `alwaysApply: true` |
| 条目生效 | 新增 `constraint` 后 `show` 里出现在「长期约束与习惯」，且 `install` 后规则里也有 |
| 合并计数 | 同样正文再 add 一次，`id` 不变、`count` +1 |
| 检索 | `search <关键词>` 能命中条目、历史指令、会话标题三类 |
| 升级不丢数据 | 重新跑 `deploy.ps1`（不带 `-ResetConfig`）后 `memory\` 文件与条目数不变 |
| 日志 | `memory\logs\memcore-YYYYMM.log` 有 `boot / sync / build / add / search` 行 |

一键核对：

```powershell
node tools\memcore.mjs stats
node tools\memcore.mjs show | Select-Object -First 20
node tools\memcore.mjs search "<最近做过的事>"
```

## 5. 版本与命名规则

- 版本号唯一来源 `payload\VERSION`；新增功能走 MINOR：`2.0.0 → 2.1.0`（`build\bump-version.ps1 -Kind minor`）
- CHANGELOG 只写“目标机可见”的变化；端口、目录、数据位置变化才算 MAJOR
- 应用目录名沿用 `payload\apps\<小写单词>`：`memcore`（无分隔符、不加版本号）
- 记忆文件命名固定：`store.json` / `MEMORY.md` / `memcore.mdc` / `notes-YYYYMM.jsonl` / `memcore-YYYYMM.log`
- 任务收尾：`scan.mjs` 刷新索引库 + git 提交（规则见 `deploy-target.mdc` §3）
